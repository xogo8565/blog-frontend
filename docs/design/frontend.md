# 프론트엔드 제품·UI/UX 설계

> 현재 작업공간에서 기존 설계 원본은 찾을 수 없어, 저장소 지침과 백엔드 OpenAPI를 기준으로 작성한 초기 설계안이다. 바뀌는 요구사항은 이 문서와 구현을 함께 갱신한다.

## 목적과 대상

한국어 기술 블로그 독자가 새 글을 발견하고, 관심 있는 주제의 글을 찾아 읽을 수 있게 한다. 공개 화면은 검색 엔진과 화면 낭독기에서 사용할 수 있도록 서버 렌더링하며, 넉넉한 여백과 간결한 글 목록, 주제 탐색을 중심으로 구성한다.

### 주요 사용자

- **방문자:** 최신 글을 훑어보고, 제목·요약·태그로 읽을 글을 고른다.
- **관심 독자:** 검색어나 태그로 주제를 좁히고, 글을 읽은 뒤 다른 글로 이동한다.
- **운영자:** 관리자 화면에서 글을 작성하고 발행한다. 관리자 UI와 인증은 공개 화면 구현 이후 별도 단계로 다룬다.

## 목표와 범위

### 첫 공개 경험 목표

- 방문자는 홈에서 발행 글 목록을 바로 확인하고 상세 글로 이동할 수 있다.
- 검색과 태그 필터는 URL로 표현해 새로고침·공유·뒤로 가기가 동작한다.
- 빈 결과, API 오류, 잘못된 검색어에도 다음 행동을 알 수 있다.
- 작은 화면과 키보드만으로도 목록, 검색, 상세 글을 사용할 수 있다.

### 첫 단계에 포함

- 홈 글 목록, 커서 기반 다음 페이지 이동
- 제목·본문 검색과 태그별 글 목록
- 발행 글 상세 화면 및 안전한 Markdown 렌더링
- 공통 헤더·푸터, 검색 입력, 날짜·태그·오류·빈 상태 UI
- 목록·검색·태그·상세 화면의 캐시 정책과 SEO 메타데이터
- 주제 탐색, 읽기 시간, 본문 목차, 글 공유, 같은 태그의 이어 읽기

### 이후 단계

- 댓글 작성·답글·삭제, 로그인·인증 흐름
- 관리자 글 목록, 편집기, 발행 작업
- 썸네일과 본문 이미지 표시. 실제 미디어 호스트를 확인해 `next/image` 허용 목록을 정한 뒤 구현한다.
- Markdown 표, 각주 등 확장 문법. 현재 렌더러가 지원한다고 명시한 문법만 사용한다.

## 정보 구조와 라우트

| 경로                    | 화면           | 데이터/API                  | 렌더링 및 캐시                                        |
| ----------------------- | -------------- | --------------------------- | ----------------------------------------------------- |
| `/`                     | 최신 글 목록   | `GET /articles`             | Server Component, 목록 데이터 `cacheLife('minutes')`  |
| `/search?q=...`         | 검색 결과      | `GET /articles/search`      | Server Component, 검색어·커서별 캐시                  |
| `/tags/[tag]`           | 태그별 글 목록 | `GET /articles?tag=...`     | Server Component, 태그·커서별 캐시                    |
| `/articles/[articleId]` | 발행 글 상세   | `GET /articles/{articleId}` | Server Component, 상세 데이터 `cacheLife('minutes')`  |
| `/admin/...`            | 운영자 화면    | 인증 API                    | 추후 설계. 사용자별 데이터는 공개 캐시에 넣지 않는다. |

목록은 API가 제공하는 정렬(`publishedAt` 내림차순)과 커서를 그대로 사용한다. 페이지 크기는 기본 10개로 고정한다. 쿼리의 `cursor`는 해석·수정하지 않고 API로 전달한다. 검색어는 2~50자이며 공백을 제거한 값을 `q`로 전달한다.

## 화면 설계

### 공통 껍데기

- 상단에는 `</>` 워드마크, `글 모음`, `주제`, `검색` 이동을 둔다. 헤더는 고정되며 대비가 있는 focus 표시를 유지한다.
- 본문 폭은 넓은 화면에서 최대 72rem, 긴 글 본문은 최대 44rem로 제한한다.
- 푸터는 블로그 성격을 짧게 설명하고 본문 상단으로 돌아가는 링크를 제공한다. 소셜 링크나 이메일은 실제 주소가 정해질 때 추가한다.
- 헤더·푸터는 서버 렌더링하며 로그인 상태나 브라우저 저장소에 의존하지 않는다.

### 홈 목록

- 짧은 소개 영역에서 블로그의 쓰기 주제와 최신 글·주제 탐색 바로가기를 보여준다.
- 최신 글은 주제 라벨, 발행일, 제목, 요약을 가진 구분선형 목록으로 표시하고, 추가 태그와 상세 이동 링크를 제공한다.
- 우측 탐색 영역에는 키워드 검색과 발행 글 수 상위 태그를 둔다. `GET /tags/top?n=8`이 비거나 실패하면 현재 페이지 글의 태그를 대신 보여준다.
- 주제 링크는 필터 결과 페이지로 이동한다. 페이지네이션은 OpenAPI의 커서를 유지하는 다음 글 링크를 사용한다.
- 글 목록 API가 실패하면 재시도 안내와 홈으로 돌아가는 경로를 보여준다. 상위 태그 조회만 실패한 경우 글 목록으로 만든 태그를 계속 제공한다.
- 다음 페이지는 `nextCursor`가 있을 때만 표시한다. 홈 한 화면에서 글 읽기·검색·주제 이동이 가능하다.
- 공개 글이 없으면 “아직 공개된 글이 없습니다”와 탐색을 막지 않는 안내를 보인다.

### 검색과 태그

- 검색은 GET 폼으로 동작한다. 입력에 `minLength=2`, `maxLength=50`을 지정하고 제출 후 검색어를 입력창에 유지한다.
- 결과는 공통 글 카드와 커서 페이지 링크를 쓴다. 결과가 없으면 검색어를 유지한 채 다시 검색할 수 있게 한다.
- API 오류 문구는 `src/shared/api/errors.ts`의 매핑을 사용한다. 검색어가 유효하지 않으면 같은 오류 매핑을 보여준다.

### 상세 글

- 글 제목을 첫 번째 `h1`로 두고 발행일과 태그를 제목 아래에 배치한다.
- 제목 영역에 대략적인 읽기 시간과 공유 동작을 제공한다. 브라우저의 Web Share를 우선 사용하고 지원하지 않으면 주소 복사로 이어간다.
- 본문에 두 개 이상의 제목이 있으면 Markdown 제목을 기준으로 목차를 만들고, 넓은 화면에서는 옆에 고정하며 좁은 화면에서는 본문 앞에 배치한다. 목차와 본문 렌더러는 같은 제목 ID 생성 규칙을 사용한다.
- 본문은 읽기 폭을 제한하고 제목·문단·목록·인용·코드 블록·안전한 링크의 간격과 대비를 분명히 한다.
- 글에 태그가 있으면 같은 태그의 다른 발행 글을 하단에 연결해 다음 읽기로 이어준다.
- 원시 HTML은 표시하거나 실행하지 않는다. 외부 링크는 새 창을 강제하지 않는다.
- 존재하지 않거나 공개되지 않은 글은 API 계약에 따라 404로 처리한다.

## 참고 사례와 적용 원칙

## 시각 언어와 디자인 토큰

- **분위기:** 화이트 캔버스와 넉넉한 여백, 선명한 제목·요약의 목록을 사용한다. 검정 포인트와 연한 회색 패널로 조작 영역을 구분하고 장식은 줄여 글 발견을 돕는다.
- **색:** 흰 배경·검정 본문·연한 회색 패널·검정 액션을 사용한다. 시스템 다크 모드에서는 검정 배경과 밝은 텍스트, 반전된 포인트 색으로 의미와 텍스트 대비를 유지한다.
- **색상 토큰:** `--background: #ffffff`, `--surface: #ffffff`, `--panel: #f7f7f7`, `--foreground: #171717`, `--muted: #666666`, `--accent: #111111`, `--accent-strong: #333333`, `--soft-accent: #f1f1f1`, `--border: #e5e5e5`. 다크 모드 색상은 `globals.css`에서 대응하는 흑백 값으로 지정한다.
- **타이포그래피:** UI와 본문은 시스템 한글 고딕체를 사용한다. 제목은 두꺼운 굵기와 짧은 행 길이로 강조한다. 외부 폰트 다운로드는 추가하지 않는다.
- **간격:** 4px 기준 간격 체계를 사용하고 주요 섹션 사이에는 32px 이상을 둔다. 홈의 글 목록과 주제 탐색은 데스크톱에서 2열, 작은 화면에서 1열이다.
- **모서리·선:** 탐색 패널은 16~20px, 입력·버튼은 10~14px, 글 목록은 저채도 구분선으로 나눈다.
- **상호작용:** 링크와 버튼에 hover, focus-visible, active 상태를 제공한다. 포커스 표시는 제거하지 않는다.
- **반응형:** 760px 미만에서는 홈·상세 본문을 한 열로 바꾸고 목차는 본문 위로 옮긴다. 520px 미만에서는 탐색 패널·관련 글·카드의 세로 간격과 조작 영역을 넓힌다.

초기 색상 토큰은 `globals.css`에 정의한다. 본문 및 보조 텍스트는 배경과 최소 WCAG AA 대비를 목표로 하고, 색상만으로 오류나 선택 상태를 전달하지 않는다.

첨부된 플로우 프로젝트 피드 화면에서는 밝은 작업 영역, 어두운 내비게이션, 명확한 조작 영역의 대비를 참고한다. 현재 색상 요구에 맞춰 이 블로그에는 블랙·화이트와 회색조 팔레트를 적용하고, 팀 목록·업무 피드 같은 협업 기능 UI는 블로그의 글 탐색 흐름과 무관하므로 추가하지 않는다.

## 동작 상태와 접근성

- 각 페이지는 의미 있는 `main`, `header`, `nav`, `footer` 구조와 페이지마다 하나의 `h1`을 가진다.
- 검색 입력은 보이는 레이블을 제공한다. 제출 버튼은 “검색”처럼 동작을 설명한다.
- 글 제목, 태그, 다음 페이지는 네이티브 링크여서 키보드와 보조 기술에서 동작한다.
- 목차는 실제 Markdown 제목의 ID로 이동하고, 공유 결과 문구는 `role="status"`로 보조 기술에 알린다.
- API 오류는 `role="alert"`, 빈 결과는 일반 설명 영역으로 표시한다.
- 로딩은 페이지 콘텐츠 높이를 유지하는 스켈레톤을 사용하고, 장식 요소는 보조 기술에서 숨긴다.
- 글 본문 코드 블록은 가로 스크롤을 허용하고 문서 전체의 가로 넘침을 만들지 않는다.
- 애니메이션을 추가할 때 `prefers-reduced-motion` 설정을 존중한다.

## 기술·API 설계

- API 요청은 `src/shared/api/client.ts`와 OpenAPI 생성 타입만 사용한다. 공개 데이터는 서버에서만 가져온다.
- 캐시 가능한 함수는 요청 매개변수를 명시적 인자로 받고, 함수 안에서 `cacheLife`와 `cacheTag`를 지정한다.
- 목록·검색·태그·상세는 `minutes` 프로필(클라이언트 stale 5분, 서버 재검증 1분, 만료 1시간)을 쓴다. 관리자 발행·발행 취소·삭제 후 태그 재검증이 구현되면 상세 글은 `days` 프로필로 늘릴 수 있다.
- 공개 목록과 검색은 `articles` 태그로 묶는다. 글별 상세는 `article:{id}` 태그를 추가해 이후 관리자 발행 기능에서 선택적으로 재검증할 수 있게 한다.
- 검색어·태그·커서는 캐시 키에 포함한다. 사용자 쿠키, access token, 비공개 초안을 공개 캐시 함수에 넣지 않는다.
- 검색 및 오류 문구는 기존 `toUserMessage()` 매핑으로 표시한다. 원시 API 오류와 내부 예외는 사용자에게 그대로 보여주지 않는다.
- `thumbnailUrl`은 응답에 있어도 현재 화면에서 사용하지 않는다. 미디어 호스트가 확정되기 전까지 원격 호스트를 넓게 허용하지 않는다.

## 성공 기준과 구현 단계

### 첫 구현의 수용 기준

- 홈·검색·태그·상세 경로가 API가 반환한 발행 콘텐츠를 서버 렌더링한다.
- 홈에서 최신 글, 검색, 주제별 이동 경로를 쉽게 찾을 수 있고, 주제 라벨·제목·요약이 구분선형 글 목록에서 빠르게 읽힌다.
- 상세 화면에서 읽기 시간, 공유, 목차, 같은 태그의 이어 읽기 경로를 사용할 수 있다.
- 목록의 다음 페이지 링크는 API `nextCursor`를 보존한다.
- 검색과 태그 값은 URL에 남아 직접 열기와 새로고침이 가능하다.
- API 오류, 빈 목록, 검색어 유효성, 없는 글에 각각 명확한 화면 상태가 있다.
- 좁은 화면에서 가로 넘침 없이 읽을 수 있고 모든 주요 조작이 키보드로 가능하다.
- raw HTML은 실행되지 않는다.

### 후속 단계

1. 댓글·로그인 UX와 공개 글 상세의 댓글 영역을 실제 백엔드 API 및 인증 구현에 연결한다. 반응·북마크는 별도 계약과 저장 정책을 먼저 설계한다.
2. 관리자 글 목록·편집기·발행 흐름과 서버 액션 권한 확인을 설계한다.
3. 실제 이미지 호스트, 사이트 도메인, 브랜드 문구를 정하고 썸네일·Open Graph 이미지를 연결한다.

- 프로덕션 API 도메인, 이미지 CDN 호스트, 사이트 도메인
- 댓글 공개 범위와 로그인 후 댓글 작성 정책
- 본문 Markdown에서 필요한 확장 문법과 표·이미지 동작
