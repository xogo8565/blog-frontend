# 프론트엔드 제품·UI/UX 설계

> 현재 작업공간에서 기존 설계 원본은 찾을 수 없어, 저장소 지침과 백엔드 OpenAPI를 기준으로 작성한 설계안이다. 바뀌는 요구사항은 이 문서와 구현을 함께 갱신한다.

## 목적과 대상

한국어 기술 블로그 독자가 새 글을 발견하고, 관심 있는 주제의 글을 찾아 읽을 수 있게 한다. 공개 화면은 검색 엔진과 화면 낭독기에서 사용할 수 있도록 서버 렌더링하며, 넉넉한 여백과 간결한 글 목록, 카테고리·태그 탐색을 중심으로 구성한다.

### 주요 사용자

- **방문자:** 최신 글을 훑어보고, 제목·요약·카테고리·태그로 읽을 글을 고른다.
- **관심 독자:** 카테고리, 검색어, 태그로 주제를 좁히고, 글을 읽은 뒤 같은 카테고리의 다른 글로 이동한다.
- **운영자:** 관리자 화면에서 카테고리를 관리하고, 이후 단계에서 글을 작성·발행한다.

## 목표와 범위

### 공개 경험 목표

- 방문자는 홈에서 발행 글 목록과 주제(카테고리)를 바로 확인하고 상세 글로 이동할 수 있다.
- 카테고리·검색·태그 필터는 URL로 표현해 새로고침·공유·뒤로 가기가 동작한다.
- 빈 결과, API 오류, 잘못된 검색어에도 다음 행동을 알 수 있다.
- 작은 화면과 키보드만으로도 목록, 카테고리 메뉴, 검색, 상세 글을 사용할 수 있다.

### 현재 범위에 포함

- 홈 글 목록, 커서 기반 다음 페이지 이동
- 상위·하위 2단계 카테고리 탐색(헤더 메뉴, 홈 주제 카드, 카테고리 페이지, 글 상세 이동 경로)
- 제목·본문 검색과 태그별 글 목록
- 발행 글 상세 화면 및 안전한 Markdown 렌더링
- 공통 헤더·푸터, 검색 입력, 날짜·카테고리·태그·오류·빈 상태 UI
- 목록·검색·태그·카테고리·상세 화면의 캐시 정책과 SEO 메타데이터
- 읽기 시간, 본문 목차, 글 공유, 같은 카테고리의 이어 읽기
- 관리자 카테고리 관리(목록·추가·수정·순서 변경·삭제). 로그인 UI는 아직 없으므로 미인증이면 로그인 안내를 보여준다.

### 이후 단계

- 댓글 작성·답글·삭제, 로그인·인증 흐름
- 관리자 글 목록, 편집기(글 카테고리 지정 포함), 발행 작업
- 썸네일과 본문 이미지 표시. 실제 미디어 호스트를 확인해 `next/image` 허용 목록을 정한 뒤 구현한다.
- Markdown 표, 각주 등 확장 문법. 현재 렌더러가 지원한다고 명시한 문법만 사용한다.

## 정보 구조와 라우트

| 경로                    | 화면           | 데이터/API                                   | 렌더링 및 캐시                                                      |
| ----------------------- | -------------- | -------------------------------------------- | ------------------------------------------------------------------- |
| `/`                     | 최신 글 목록   | `GET /articles`, `/categories`, `/tags/top`  | Server Component, `cacheLife('minutes')`                            |
| `/categories/[slug]`    | 카테고리별 글  | `GET /categories`, `GET /articles?category=` | Server Component, 슬러그·커서별 캐시. 공개 트리에 없는 슬러그는 404 |
| `/search?q=...`         | 검색 결과      | `GET /articles/search`                       | Server Component, 검색어·커서별 캐시                                |
| `/tags/[tag]`           | 태그별 글 목록 | `GET /articles?tag=...`                      | Server Component, 태그·커서별 캐시                                  |
| `/articles/[articleId]` | 발행 글 상세   | `GET /articles/{articleId}`, `/categories`   | Server Component, 상세 데이터 `cacheLife('minutes')`                |
| `/admin/categories`     | 카테고리 관리  | `/me`, `/admin/categories/*`                 | 클라이언트 렌더링(TanStack Query). 공개 캐시에 넣지 않고 색인 제외  |

목록은 API가 제공하는 정렬(`publishedAt` 내림차순)과 커서를 그대로 사용한다. 페이지 크기는 기본 10개로 고정한다. 쿼리의 `cursor`는 해석·수정하지 않고 API로 전달한다. 검색어는 2~50자이며 공백을 제거한 값을 `q`로 전달한다. 카테고리 페이지는 상위 카테고리면 하위 카테고리의 글을 함께 보여준다(API 규칙).

## 화면 설계

### 공통 껍데기

- 상단에는 `</>` 워드마크, `글 모음`, `카테고리` 펼침 메뉴, `검색`을 둔다. 카테고리 메뉴는 네이티브 `<details>`로 키보드에서 열고 닫으며, 링크를 누르거나 바깥을 누르거나 Escape를 누르면 닫는다(헤더가 페이지 이동 뒤에도 남기 때문). 공개 카테고리가 없으면 메뉴 대신 `태그`(홈의 태그 목록)로 이동한다.
- 메뉴 패널은 상위 카테고리별로 하위 카테고리와 발행 글 수를 보여준다. 760px 미만에서는 화면 폭에 맞춘 고정 패널이 된다.
- 본문 폭은 넓은 화면에서 최대 74rem, 긴 글 본문은 최대 46rem로 제한한다.
- 푸터는 블로그 소개, 최근 글 4개, 상위 카테고리, 인기 태그 열과 본문 상단으로 돌아가는 링크를 제공한다. 데이터가 없는 열은 생략한다.
- 헤더·푸터 데이터는 루트 레이아웃이 `'use cache'` 함수로 조회해 props로 넘긴다. 로그인 상태나 브라우저 저장소에 의존하지 않는다.

### 홈 목록

- 소개 영역은 블로그 이름 `h1`("개발 노트")과 설명, 같은 줄의 검색 폼으로 구성한다. 첫 화면에서 주제와 최신 글이 보이도록 높이를 낮게 유지한다.
- "주제 둘러보기"는 글이 있는 카테고리 최대 4개를 글 수 순으로 카드로 보여준다. 카드는 상위 카테고리 이름·색 견본, 이름, 설명, 글 수를 갖는다. 순위 표시는 하지 않는다. 첫 페이지에서만 보여준다.
- 최신 글은 카테고리 라벨(상위 › 하위), 발행일, 제목, 요약, `#태그`를 가진 구분선형 목록이며, 오른쪽에 장식용 커버(카테고리 색조 + `/slug` + 이름)를 둔다. 미분류 글은 첫 태그를 라벨로 쓴다. 카드 전체가 제목 링크의 클릭 영역이며 별도 "읽기" 링크는 두지 않는다.
- 우측 레일에는 카테고리 트리(글 수 포함)와 인기 태그를 둔다. `GET /tags/top?n=8`이 비거나 실패하면 현재 페이지 글의 태그를 대신 보여준다. 트리가 길 수 있어 레일은 고정(sticky)하지 않는다.
- 페이지네이션은 OpenAPI의 커서를 유지하는 다음 글 링크를 사용한다. 홈의 다음 글 링크는 `#latest`로 이동한다. 커서로 이동한 페이지에는 "처음으로" 링크를 함께 둔다.
- 글 목록 API가 실패하면 재시도 안내를 보여준다. 카테고리·태그 조회만 실패하면 해당 영역을 생략하고 목록은 계속 보여준다.
- 공개 글이 없으면 “아직 공개된 글이 없습니다”와 탐색을 막지 않는 안내를 보인다.

### 카테고리

- 이동 경로(홈 › 상위 › 현재), 상위 카테고리 이름과 색 견본, `h1` 이름, 설명, 발행 글 수, 하위 카테고리 칩을 보여준다.
- 글 목록은 공통 글 카드와 커서 페이지 링크를 쓴다. 비면 "이 카테고리에는 아직 글이 없습니다"를 보여준다.
- 오른쪽 레일의 카테고리 트리에서 현재 카테고리를 `aria-current="page"`로 표시한다. 760px 미만에서는 레일이 목록 뒤로 간다.
- 숨김 카테고리는 공개 트리에 없으므로 이 화면은 404다.

### 검색과 태그

- 검색은 GET 폼으로 동작한다. 입력에 `minLength=2`, `maxLength=50`을 지정하고 제출 후 검색어를 입력창에 유지한다.
- 결과는 공통 글 카드와 커서 페이지 링크를 쓰고, 카드의 제목·요약에서 검색어와 일치하는 부분을 `<mark>`로 강조한다. 결과가 없으면 검색어를 유지한 채 다시 검색할 수 있게 한다.
- 검색어가 없거나 결과가 없으면 `GET /tags/top?n=6`의 상위 태그를 "이런 주제는 어때요?" 추천으로 보여준다. 태그 페이지가 비었을 때도 현재 태그를 뺀 추천을 보여준다. 추천 조회가 비거나 실패하면 추천 영역을 생략한다.
- API 오류 문구는 `src/shared/api/errors.ts`의 매핑을 사용한다. 검색어가 유효하지 않으면 같은 오류 매핑을 보여준다.

### 상세 글

- 카테고리가 있으면 제목 위에 이동 경로(홈 › 상위 › 카테고리)를, 없으면 "글 모음"으로 돌아가는 링크를 둔다. 숨김 카테고리는 링크 없이 이름만 표시한다.
- 글 제목을 첫 번째 `h1`로 두고 발행일, 읽기 시간, 수정일, 공유, 태그를 제목 아래에 배치한다. 공유는 Web Share를 우선 사용하고 지원하지 않으면 주소 복사로 이어간다.
- 본문에 두 개 이상의 제목이 있으면 Markdown 제목을 기준으로 목차를 만들고, 넓은 화면에서는 옆에 두며 좁은 화면에서는 본문 앞에 접힌 `<details>` 목차로 배치한다. 목차와 본문 렌더러는 같은 제목 ID 생성 규칙을 사용한다.
- 넓은 화면의 옆 영역에는 "이 글의 카테고리" 카드(설명, 글 수, 카테고리로 가는 링크)를 함께 둔다. 목차와 카테고리 카드가 모두 없으면 옆 영역을 렌더링하지 않는다.
- 본문은 읽기 폭을 제한하고 제목·문단·목록·인용·코드 블록·안전한 링크의 간격과 대비를 분명히 한다. 목록은 기호와 번호를 표시하고(Tailwind preflight 초기화를 본문에서 되돌린다), 언어가 지정된 코드 블록은 언어 이름을 위에 표시한다.
- 하단 이어 읽기는 같은 카테고리의 다른 발행 글을, 공개 카테고리가 없으면 첫 태그의 글을 보여준다.
- 원시 HTML은 표시하거나 실행하지 않는다. 외부 링크는 새 창을 강제하지 않는다.
- 존재하지 않거나 공개되지 않은 글은 API 계약에 따라 404로 처리한다.

### 관리자 카테고리 관리

- 가드: `/me`가 401이면 "로그인이 필요합니다"와 Google 로그인 시작 링크, ADMIN이 아니면 권한 안내를 보여준다. 가드는 화면 편의용이고 권한 판단은 API가 한다.
- 표: 상위 카테고리 뒤에 하위 카테고리를 들여 쓴 목록으로 이름, 슬러그, 글 수(상위는 하위 포함), 공개 상태, 작업(위로·아래로·수정·삭제)을 보여준다. 작업 버튼은 대상 이름을 포함한 접근 가능한 이름을 가진다.
- 편집 패널: 이름(1~30자), 슬러그(`^[a-z0-9]+(-[a-z0-9]+)*$`, 40자 이내, 영문 이름이면 자동 제안), 상위 카테고리, 설명(200자 이내), 공개 여부. 형식 오류와 서버의 중복 슬러그 오류는 해당 필드에 `aria-invalid`와 오류 문구로 보여준다. 하위가 있는 카테고리는 상위를 바꿀 수 없다(2단계 제한).
- 삭제: 네이티브 `<dialog>`로 확인한다. 하위 카테고리가 있으면 막고, 글이 있으면 옮길 카테고리를 골라야 삭제할 수 있다.
- 결과는 `role="status"` 문구로 알린다. 변경에 성공하면 목록을 다시 받고, 공개 화면 캐시를 비우는 Server Action을 호출한다.

## 시각 언어와 디자인 토큰

- **분위기:** 화이트 캔버스와 넉넉한 여백, 선명한 제목·요약의 목록을 사용한다. 검정 포인트와 연한 회색 패널로 조작 영역을 구분한다. 강한 장식 이미지나 큰 어두운 배너 없이 블로그 고유의 흑백 톤을 유지한다.
- **색:** 흰 배경·검정 본문·연한 회색 패널·검정 액션을 사용한다. 시스템 다크 모드에서는 검정 배경과 밝은 텍스트, 반전된 포인트 색으로 대비를 유지한다.
- **색상 토큰:** `--background: #ffffff`, `--surface: #ffffff`, `--panel: #f7f7f7`, `--foreground: #171717`, `--muted: #666666`, `--accent: #111111`, `--accent-strong: #333333`, `--soft-accent: #f1f1f1`, `--border: #e5e5e5`, `--danger: #b3323c`. 다크 모드 값은 `globals.css`에서 지정한다.
- **카테고리 색:** 길찾기 표시(색 견본, 라벨, 커버 색조)에만 쓰는 6가지 톤(`--tone-1`~`--tone-6`, 미분류 `--tone-0`)이다. API에 색 필드가 없으므로 상위 카테고리 슬러그에서 계산해(`src/shared/lib/category-tone.ts`) 어느 화면에서나 같은 색을 쓴다. 흰 배경에서 글자로 써도 4.5:1 이상인 값을 쓰고, 다크 모드에서는 밝은 값으로 바꾼다. 색만으로 정보를 전달하지 않고 항상 이름을 함께 보여준다.
- **타이포그래피:** UI와 본문은 시스템 한글 고딕체를 사용한다. 커버의 경로 표시만 시스템 고정폭 글꼴을 쓴다. 외부 폰트 다운로드는 추가하지 않는다.
- **간격:** 4px 기준 간격 체계를 사용하고 주요 섹션 사이에는 32px 이상을 둔다. 홈·카테고리 화면은 데스크톱에서 목록과 레일 2열, 작은 화면에서 1열이다.
- **모서리·선:** 탐색 패널은 16~20px, 입력·버튼은 10~14px, 글 목록은 저채도 구분선으로 나눈다. 주제 카드는 위쪽 3px 카테고리 색 선으로 구분한다.
- **상호작용:** 링크와 버튼에 hover, focus-visible, active 상태를 제공한다. 포커스 표시는 제거하지 않는다.
- **반응형:** 760px 미만에서는 홈·카테고리·상세 본문을 한 열로 바꾸고 목차는 본문 위로 옮긴다. 홈의 주제 카드는 가로로 넘겨 보고, 카테고리·태그 레일은 목록 뒤로 간다. 520px 미만에서는 커버를 작은 정사각형으로 줄이고 태그·라벨의 조작 영역을 36px 이상으로 넓힌다.
- **아이콘·기호:** 내부 링크에는 외부 이동을 뜻하는 `↗`를 쓰지 않는다. 이동은 `→`, 페이지 내 이동은 `↓`/`↑`, 검색은 돋보기 아이콘을 쓰고 장식 기호는 보조 기술에서 숨긴다.
- **글자 크기:** 메타 정보·라벨도 13px(0.8125rem) 이상, 라벨 칩은 12px 이상으로 둔다. 한글 제목의 자간은 -0.04em보다 좁히지 않는다.

## 동작 상태와 접근성

- 각 페이지는 의미 있는 `main`, `header`, `nav`, `footer` 구조와 페이지마다 하나의 `h1`을 가진다.
- 검색 입력은 보이는 레이블을 제공한다. 제출 버튼은 “검색”처럼 동작을 설명한다.
- 글 제목, 카테고리, 태그, 다음 페이지는 네이티브 링크여서 키보드와 보조 기술에서 동작한다. 이동 경로는 `nav aria-label="이동 경로"`와 `aria-current="page"`를 쓴다.
- 글 수처럼 숫자만 보이는 값에는 "개의 글" 같은 숨김 텍스트를 붙인다.
- 목차는 실제 Markdown 제목의 ID로 이동하고, 공유·관리 결과 문구는 `role="status"`로 보조 기술에 알린다.
- API 오류는 `role="alert"`, 빈 결과는 일반 설명 영역으로 표시한다.
- 로딩은 페이지 콘텐츠 높이를 유지하는 스켈레톤을 사용하고, 장식 요소(커버, 색 견본)는 보조 기술에서 숨긴다.
- 글 본문 코드 블록과 관리자 표는 가로 스크롤을 허용하고 문서 전체의 가로 넘침을 만들지 않는다.
- 애니메이션을 추가할 때 `prefers-reduced-motion` 설정을 존중한다.

## 기술·API 설계

- API 요청은 `src/shared/api/client.ts`와 OpenAPI 생성 타입만 사용한다. 공개 데이터는 서버에서만 가져온다.
- 캐시 가능한 함수는 요청 매개변수를 명시적 인자로 받고, 함수 안에서 `cacheLife`와 `cacheTag`를 지정한다.
- 목록·검색·태그·카테고리·상세는 `minutes` 프로필(클라이언트 stale 5분, 서버 재검증 1분, 만료 1시간)을 쓴다.
- 공개 목록과 검색은 `articles`, 카테고리 트리와 카테고리 필터 목록은 `categories` 태그를 함께 단다. 글별 상세는 `article:{id}` 태그를 추가한다.
- 관리자 변경 후에는 Server Action(`src/features/category/actions/revalidate.ts`)이 넘겨받은 access 토큰으로 `/me`를 호출해 ADMIN을 확인한 뒤 `updateTag('categories')`, `updateTag('articles')`로 공개 캐시를 바로 비운다. 토큰은 저장하지 않는다.
- 헤더 펼침 메뉴는 `usePathname`을 쓰지 않는다. Cache Components에서 동적 경로의 레이아웃이 Suspense 없이 멈추기 때문이며, 대신 링크 클릭·바깥 클릭·Escape로 닫는다.
- 검색어·태그·카테고리·커서는 캐시 키에 포함한다. 사용자 쿠키, access token, 비공개 초안을 공개 캐시 함수에 넣지 않는다.
- 검색 및 오류 문구는 기존 `toUserMessage()` 매핑으로 표시한다. 원시 API 오류와 내부 예외는 사용자에게 그대로 보여주지 않는다.
- `thumbnailUrl`은 응답에 있어도 현재 화면에서 사용하지 않는다. 미디어 호스트가 확정되기 전까지 원격 호스트를 넓게 허용하지 않는다.

## 성공 기준과 구현 단계

### 수용 기준

- 홈·카테고리·검색·태그·상세 경로가 API가 반환한 발행 콘텐츠를 서버 렌더링한다.
- 홈에서 최신 글, 검색, 카테고리·태그 이동 경로를 쉽게 찾을 수 있고, 카테고리 라벨·제목·요약이 구분선형 글 목록에서 빠르게 읽힌다.
- 상세 화면에서 읽기 시간, 공유, 목차, 카테고리 이동 경로, 같은 카테고리의 이어 읽기 경로를 사용할 수 있다.
- 관리자는 카테고리를 추가·수정·정렬·삭제할 수 있고, 규칙 위반(형식, 중복 슬러그, 하위·글이 있는 삭제)은 화면에서 이유를 알 수 있다.
- 목록의 다음 페이지 링크는 API `nextCursor`를 보존한다.
- 카테고리·검색·태그 값은 URL에 남아 직접 열기와 새로고침이 가능하다.
- API 오류, 빈 목록, 검색어 유효성, 없는 글·카테고리에 각각 명확한 화면 상태가 있다.
- 좁은 화면에서 가로 넘침 없이 읽을 수 있고 모든 주요 조작이 키보드로 가능하다.
- raw HTML은 실행되지 않는다.

### 후속 단계

1. 백엔드에 카테고리 도메인·저장소·엔드포인트를 구현한다(계약은 OpenAPI에 정의됨).
2. 댓글·로그인 UX와 공개 글 상세의 댓글 영역을 실제 백엔드 API 및 인증 구현에 연결한다.
3. 관리자 글 목록·편집기(카테고리 지정 포함)·발행 흐름과 서버 액션 권한 확인을 구현한다.
4. 실제 이미지 호스트, 사이트 도메인, 브랜드 문구를 정하고 썸네일·Open Graph 이미지를 연결한다.
